# M2 Phase A Plan: RecombineAgent Autonomous Query

Date: 2026-08-28

Goal: prove that RecombineAgent can decide its own ClickHouse queries through
`mcp-clickhouse`, retrieve aggregate evidence, and leave an auditable trace. This
phase is about autonomous database use, not final structured proposal output.
`TreatmentProposal` convergence belongs to Phase B.

## Starting Point

M1 is ready enough for agent work:

- `films`: 1,238 rows, one per film, 1990-2014.
- `film_attention`: 4,937,204 pageview rows.
- `mv_archetype_performance`: verified against `films` for 120 cells.
- `mv_motif_pair_stats`: all 417 pairs verified against `films` on count and
  ROI median, plus no self-pairs.
- `mv_interest_by_year`: all 14,605 (film_id, calendar_year) cells verified
  against `film_attention`.
- Low-signal interest rows are excluded from MV interest aggregates through
  `has_interest_signal` and `interest_sample_count`.
- `app/prompts.py` already carries DDL, vocabulary, AggregatingMergeTree query
  guidance, sample-size rules, and interest caveats.

Known caveat: `scripts/verify_mv.py` passes functionally. Latency was being read
off a single cold sample and consecutive runs reported 276 ms and 525 ms for the
same queries; it now runs each query five times and judges the median. Latest
medians 215-248 ms, worst tail 329 ms. Not a Phase A blocker.

Resolved during Phase A: query guardrails moved from a grep in the verification
step to `app/guardrails.py`, applied live to every query the agent issues and
recorded in the trace beside it.

## Scope

Implement the smallest runtime path that demonstrates:

1. Gemini receives the real analyst system instruction from `app/prompts.py`.
2. Gemini has `clickhouse_tools` from `app/mcp.py`.
3. Gemini chooses and runs queries without being handed exact SQL.
4. The trace records every tool call, result/error, row preview, and final model
   synthesis.
5. The final synthesis names candidate recombinations using only controlled
   vocabulary terms and cites sample counts.

Out of scope for Phase A:

- `response_schema=TreatmentProposal`.
- wildcard/high-temperature branch.
- `PredictAgent` scoring.
- FastAPI/SSE frontend integration.
- Imagen/TTS/storyboard generation.

## Implementation Shape

Create:

- `app/agents/__init__.py`
- `app/agents/recombine.py`
- `scripts/run_m2_recombine_phase_a.py`
- `docs/m2-recombine-phase-a-trace.log` generated by the script

`app/agents/recombine.py` should expose a factory, not a global agent:

```python
def build_recombine_phase_a_agent(model: str, toolset) -> Agent:
    ...
```

The instruction should compose:

- `analyst_system_instruction()`
- a RecombineAgent-specific task:
  - find historically strong structural combinations;
  - start broad, then narrow only if sample counts survive;
  - compare ROI and sustained-interest evidence separately;
  - use `interest_sample_count` for interest claims;
  - report insufficient evidence instead of forcing a claim;
  - produce a short text synthesis, not JSON.

`scripts/run_m2_recombine_phase_a.py` should follow the proven M0 pattern:

- `load_env()`
- choose `MODEL_FAST` or `gemini-2.5-flash`
- create `toolset = build_clickhouse_tools()`
- create ADK `Agent`, `InMemorySessionService`, and `Runner`
- run one prompt such as:

```text
Find two promising narrative recombinations for a mid-budget original film.
Use the database yourself. Start broad, cite sample counts, and do not invent
columns or vocabulary terms.
```

- write redacted trace to `docs/m2-recombine-phase-a-trace.log`
- always `await toolset.close()` in `finally`

## Query Behavior To Encourage

The agent should discover evidence from at least two of these surfaces:

- `mv_archetype_performance`
- `mv_motif_pair_stats`
- `films`

Preferred pattern:

1. Broad archetype scan:
   - rank archetypes by `countMerge(sample_count)`, ROI median/p75, and interest
     median.
2. Broad motif pair scan:
   - rank motif pairs by sample count and ROI median, using `HAVING n >= 8`.
3. Narrow check:
   - verify one chosen combination in `films` with `has(...)` filters.

Avoid:

- filtering by `release_bucket` before checking broad sample count;
- using raw `interest_median_daily` for cross-film comparison;
- treating missing interest evidence as `0`;
- nesting `countMerge(...)` inside `sum(...)` without a subquery;
- selecting raw aggregate states.

## DoD

Phase A is done when one command:

```bash
./scripts/run_etl.sh scripts/run_m2_recombine_phase_a.py
```

produces a trace showing:

- at least 2 `run_query` tool calls chosen by Gemini;
- at least 2 successful ClickHouse tool responses;
- at least one query against an MV, not only `SELECT 1` or `list_tables`;
- sample counts visible in the query result or final synthesis;
- final text synthesis proposes at least two recombination directions;
- no write queries;
- no use of columns removed from the spec, such as `pageview_peak` or
  `pageview_decay_days`;
- no interest claim that uses ROI `sample_count` in place of
  `interest_sample_count`;
- trace log committed or otherwise available under `docs/`.


Acceptance notes:

- `verify_mv.py` latency may fluctuate on ClickHouse Cloud. Treat a single
  slight >500 ms result as warning, not an M2 blocker.
- If Gemini produces one bad query, let the trace show the failure. Phase A
  proves autonomy, and SQL self-correction becomes a stronger requirement in
  PredictAgent.

## Risks

- The model may summarize without calling tools. Mitigation: instruction says it
  must query first, and the script should fail if calls/responses are zero.
- The model may use old names from memory. Mitigation: `app/prompts.py` injects
  the real DDL and the verification grep checks removed columns.
- The model may over-narrow into thin cells. Mitigation: prompt already requires
  broad-first querying and `HAVING n >= MIN_SAMPLE_SIZE`.
- ADK and `mcp-clickhouse` dependency conflict can return. Mitigation: continue
  using `app.mcp.build_clickhouse_tools()` and `uv run --with mcp-clickhouse`
  subprocess isolation.

## Next Step After Phase A

Phase B should take the Phase A transcript as context and run a no-tools
structured call with `response_schema=TreatmentProposal`, producing one grounded
proposal first. The wildcard branch should remain separate and only be added
after the grounded proposal validates.
